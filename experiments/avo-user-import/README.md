# Импорт пользователей МВЦ из АВО

Источник — приватная локальная выгрузка `exports/contacts-api-all-fields/contacts.sqlite`,
доступ только на чтение. Назначение — `my-lk.mv-centr.ru`; аккаунты других АВО
в этот импорт не входят. Сценарий создаёт пользователей сайта с номером контакта
АВО, исходным паролем и без приветственного письма. Доступы к курсам не выдаёт.

По умолчанию работает предварительная проверка. Запись запускается с `--apply
--limit N`. Сценарий использует журнал уже созданных записей и не ищет заранее
совпадения телефонов. Frappe проверяет уникальность email и ID АВО при записи;
существующие аккаунты не изменяются. Конфликты, неподходящие данные и подтверждённые записи
фиксируются только по номеру контакта в приватном JSONL-журнале в каталоге
выгрузки, без почт, телефонов, паролей и ссылок. После 10 проблем подряд пакет
останавливается; при неопределённом результате записи останавливается сразу.
Неопределённые результаты записи требуют сверки до повторного запуска.

Исходники `lms/lms/avo_user_import.py` и `avo_contact_fields.py` документируют
установленный на МВЦ импорт и поля связи. Пароли, ключи и экспортные данные
в репозиторий не включаются. На 09.11.2026 выполнены тесты импортёра и
небольшие проверочные партии; перенос всей базы ещё не завершён.

09.11.2026 в МВЦ разрешены одинаковые `User.mobile_no`: установлена настройка
Frappe и уникальный индекс заменён обычным через `allow_shared_phones.py`.
Вход по номеру на сайте выключен; вход по email проверен для двух тестовых
пользователей с одним номером на отдельном стенде. По уточнению владельца
та же настройка применена отдельно на сайтах ИОМП и Master Vision. Перед
изменением каждой базы проверена резервная копия. Контакт АВО 10 по решению владельца исключён из импорта и его ранее
созданная запись отключена, а контакт 11 создан; записи 3 и 4 сохранены.

На стенде проверено обновление схемы `User`: настройка неуникального номера и
обычный индекс сохраняются. Для каждого сайта добавлена настройка индекса;
перед закреплением сделаны свежие проверенные резервные копии всех трёх БД.

09.11.2026 импорт остановился на перегруженной очереди Frappe. Последняя запись
сверена по ID и почте: пользователь не создался. Очередь разгрузилась; добавлена
пауза по умолчанию в одну секунду между создаваемыми записями. При повторной
ошибке или неизвестном результате импорт остановится и оставит журнал.

Ограничение штатной регистрации — 60 пользователей за 60 минут. Для импорта
администратором на МВЦ его обход действует только в обработчике `before_insert`
конкретной записи; остальные этапы создания остаются в обычном режиме.
На тестовом стенде проверены обычная регистрация, импорт и вход с паролем.
Образ обновлён с резервной копией и проверкой сервисов; в нём 8 слоёв.

Фоновый запуск `run_background.py` использует отдельную блокировку от повторного
запуска и пишет состояние и агрегированный журнал только в приватный каталог
выгрузки. После остановки или обработки выгрузки показывает сообщение Windows;
при неопределённом результате записи возобновление возможно после сверки.
Создание записей с неподходящим email и других конфликтных случаев не считается
полным переносом: номера этих контактов сохраняются в журнале для разбора.

Контакты без корректной почты сохраняются отдельно как `Contact` с ID АВО,
аккаунтом и идентификаторами соцсетей: выдуманная почта не назначается.
Команда `import_contacts_no_email.py --apply --limit N` создаёт их в МВЦ;
без `--apply` работает предварительная проверка. Они не являются учётными
записями для входа, пока не настроена проверенная авторизация Telegram/VK.
Пароли и персональные данные в журнал не записываются.

Для фонового переноса этих записей используется `run_background.py --no-email`.
У него отдельные блокировка, состояние и уведомление об остановке; между
записями выдерживается пауза две секунды. Поля идентификаторов ограничены
уровнем доступа 1. На отдельном стенде проверено, что пользователь сайта не
может читать чужой Contact; создание без почты и с одинаковым телефоном также
проверено. Неопределённый результат записи требует сверки перед повторным запуском.
