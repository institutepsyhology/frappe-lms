# Модель персональных доступов: проект для реализации

Состояние: проект, не схема работающей БД. Начата реализация документов Frappe `LMS Access Grant`, `LMS Access Grant Lesson`, `LMS Access Policy` и функции чтения записи для ученика и урока. В разрешения урока и другие маршруты добавлены точки подключения; политика выключена по умолчанию и требует одновременно серверного разрешения и настройки конкретного курса. Изменения не установлены на рабочих сайтах и охватывают только часть этой модели. Часть сценариев испытана на изолированном Frappe-стенде; подробные границы в `VERIFICATION.md`. Точные поля и проверки нужно подтвердить дополнительными тестами и примерами курсов АВО. Все сроки и признаки, которых источник не сообщил или смысл которых не подтверждён, сохраняются как неизвестные; неизвестное не означает разрешение.

## Записи и связи

1. **Правила курса.** Курс; режим использования персональной политики; варианты точки отсчёта для обучения и каждого урока; тип общего срока: дата/число дней/бессрочно; общие даты курса; правила заморозки, возобновления и повторного зачисления; настройки видимости и сценарии проверки работ. Политика включается явно для выбранного курса, не для всех курсов разом.
2. **Персональные переопределения.** Ученик + курс; для каждой настройки отдельное состояние «наследовать», «задано значение» или «неизвестно». Ложь, 0 и бессрочный срок не равны отсутствию настройки. Отдельно хранить личное открытие/закрытие, флаг игнорирования общей даты и срок проверки заданий.
3. **Основание доступа.** Ученик + курс + источник + устойчивый ID события/покупки/ручной выдачи + состояние + даты + причины изменений. Одна покупка может затрагивать несколько курсов и областей, а один курс — иметь несколько независимых оснований. Отзыв конкретного основания не стирает другие. Правила пересечения заморозок и расписаний для разных оснований требуют проверки АВО.
4. **Область основания.** Ссылка на курс/раздел/урок или конкретный набор уроков. Явно различать «все уроки курса, включая добавленные позже» и «снимок выбранных уроков», если проверка АВО подтвердит оба режима. При обращении к конкретному уроку курс определяется сервером из самой записи урока; параметры клиента об этом не считаются доказательством.
5. **Персональное состояние урока.** Урок, назначение, сохранённый флаг доступности, скрытие, индивидуальный день и другие источниковые значения — отдельные поля. Нужно проверить влияние каждого флага на список, прямой переход и контент; вычисленные условия и исходные факты не смешиваются.
6. **Журнал и события.** Кто, что, когда, по какому основанию изменил; идемпотентный внешний идентификатор и версия события. Входящие повторы, устаревшие события и неполные снимки не должны отзывать действующие права. Выходящие события интеграции сохраняются в очереди с повтором; передача отключена на тестовом стенде.
7. **Связь с АВО.** Пространство аккаунта АВО + ID контакта + ID курса + ID карточки личного доступа + ID урока. Email может измениться и не является единственным ключом. Таблицы сопоставления и отчёт о неоднозначных совпадениях готовятся до переноса; персональные данные и реальные ссылки не попадают в публичный GitHub.

## Особенности действий

* Выдача курса и отдельного урока, изменение личных сроков, продление, закрытие, скрытие и полное удаление доступа — разные команды. У группы учеников действие сначала отображает выбранный объём, а затем выполняется с журналом результатов для каждого ученика.
* Заморозка и разморозка используют **конфигурацию конкретного курса и личное переопределение**, если оно разрешено правилами. Продление срока и сдвиг расписания — разные операции. По уточнению пользователя заморозка не удаляет домашние задания.
* При ручном закрытии или полном удалении доступа администратор выбирает, что делать с домашними заданиями и прогрессом; предварительный просмотр показывает охват. Повторное предоставление доступа может сохранять прохождение или запускать обучение заново. Фактическое удаление доступно только уполномоченному оператору и не выполняется в тестах на реальных данных.
* После закрытия курса в зависимости от настроек может сохраняться доступ к части уроков, в частности к ранее посещённым или пройденным. Критерий и срок сохранения доступа нужно сопоставить с конкретной настройкой АВО; эти данные не сводятся к одному полю окончания курса.
* Даты с точным временем сравниваются как моменты времени. Правила АВО с календарными днями, границами даты и возможными часовыми поясами проверяются отдельно, а не выводятся из приблизительного `24 часа`.

## Маршрут проверки

Источник истины пользователя — сессия сервера. Сервер находит курс по уроку, применяет права автора/пробного просмотра и правила доступа обучающегося, а при нескольких основаниях проверяет допустимые сценарии их совместного действия. Обращения за текстом, вложением, тестом, заданием и изменением прогресса принимают решение на стороне сервера. Список уроков должен отражать ту же политику, что и прямой доступ. Уроки нескольких курсов, общие файлы, тесты и SCORM-пакеты требуют отдельных тестов.

Нельзя считать, что один hook закрывает всё: в Frappe условия `get_list` не распространяются на `get_all`, а в LMS есть маршруты с прямым чтением. Перед выпуском нужен список всех точек входа и отказ при ошибке решения для курса с включённой политикой; простой fallback к старой логике допускается только для курса, где персональная политика явно не включена.

## Приёмка

На изолированном стенде создать синтетический курс, трёх учеников и отдельного автора. Проверить полный и выборочный доступ, группы, разные личные/общие даты, несколько оснований, заморозки, продления, точные границы, скрытые и будущие уроки, отчёты разных типов, отзыв и повторный доступ; каждое действие проверить через интерфейс, MCP и прямые маршруты. Отдельно проверить ошибку хранилища и незнакомые данные, повторы событий, конкурентные изменения, объём БД и корректный откат без потери чужих прав. Совпадение с АВО подтверждается только сравнением на конкретных сценариях с известными настройками.
