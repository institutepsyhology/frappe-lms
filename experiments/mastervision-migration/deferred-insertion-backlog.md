# Отложенные уроки Master Vision: вставка в исходный порядок

Статус будущего режима: **NOT IMPLEMENTED**. Отсрочка шести уроков разрешает
текущий перенос остальных материалов, но не означает автоматическое восстановление
всех пропусков после исправления источника.

Область: только Master Vision (`mastervision`, `shop.mastervision.su` →
`my-lk.mastervision.su`). Это технический backlog; исходные тексты, ссылки на
материалы и персональные данные сюда не включаются.

## Текущий безопасный перенос

| Курс | Полный снимок | Сейчас переносится | Отложен |
| --- | ---: | ---: | ---: |
| 607 | 40 | 39 | 6577 |
| 624 | 40 | 39 | 7050 |
| 627 | 50 | 49 | 7198 |
| 628 | 50 | 49 | 7247 |
| 629 | 1 | 0 | 7252 |
| 630 | 40 | 39 | 7295 |
| Итого | 221 | 215 | 6 |

Проверка до запуска подтвердила полные привязанные checkpoints и 221 уникальный
исходный ID. Проекция отбора сохраняет исходные payloads и относительный порядок;
полный список уроков и все шесть отложенных снимков остаются в архиве. На момент
этой проверки во Frappe не было ни одного из шести курсов и ни одного из 221
исходного ID уроков.

В `run.py` отбор выполняется перед `Importer.import_course`. Для пяти непустых
проекций импортёр проверяет все выбранные уроки, затем создаёт только их, сохраняя
исходные `custom_avo_id` и `custom_lms_id`. `Lesson Reference.idx` становится
непрерывным `1..N` для выбранного порядка; это позиция, а не ID урока. Источник не
меняется. Публикация, выдача доступов и заглушки в этот перенос не входят.

У курса 629 исходный снимок непустой, но после отбора остаётся ноль уроков. Он
попадает в ветку отсрочки до вызова импортёра; создавать фиктивный пустой курс
через `ensure_empty_course` здесь не требуется.

## Четыре подтверждённых препятствия будущей вставке

Позиции ниже считаются с единицы в полном исходном порядке, **без сортировки по
числовому ID**.

| Курс / урок | Исходная позиция | Уже переносимые уроки после пропуска |
| --- | --- | --- |
| 624 / 7050 | 39 из 40 | 7051 |
| 627 / 7198 | 47 из 50 | 7191, 7192, 7200 |
| 628 / 7247 | 47 из 50 | 7241, 7251, 7249 |
| 630 / 7295 | 39 из 40 | 7296 |

В `importer.py`, `Importer.import_course`, текущая защита требует префикс:

```python
existing = initial["ids"]
if existing != ids[:len(existing)] or len(existing) > len(ids):
    raise Review("course_order_conflict")
```

После нынешнего переноса список без среднего урока не будет префиксом полного
списка. Повторный обычный запуск остановится с `course_order_conflict` **до
предпросмотров и записей**. Это подтверждено синтетическими проверками текущего
импортёра. Серверный `create_lesson` также добавляет новую ссылку в конец главы.

607 / 6577 — последний урок, позиция 40 из 40: обычное добавление в конец подходит.
629 / 7252 — единственный урок: когда он будет готов, допустимо обычное создание
реального курса вместе с уроком.

## Checkpoint и неизменность уже перенесённых материалов

Новый digest полного checkpoint после исправления отложенного урока сам по себе
не решит конфликт порядка. Серверный `_fingerprint` зависит от payload конкретного
урока и хешей его изображений; digest общего checkpoint в него не включён.
Неизменённые выбранные payloads сохраняют свои fingerprints при обновлении только
отложенного урока и привязки checkpoint.

Реальное изменение уже перенесённого payload, названия курса или образов остаётся
конфликтом. Автоматически перезаписывать такие материалы или ослаблять проверку
`source_original_ape` / `avo-source-sha256-*.json` нельзя.

## Предложение без изменения схемы

Отдельный явно включаемый режим добавляет только разрешённые отсутствующие уроки,
после проверки уже существующих ID как упорядоченной подпоследовательности полного
источника. Затем он атомарно восстанавливает порядок ссылок в пределах той же главы.
План: клиент и при необходимости узкий whitelisted MCP API для атомарного
упорядочивания главы; новая схема БД или перенос существующих тел уроков не нужны.

Существующий `lms.lms.api.update_lesson_index` умеет менять позиции, но не принимает
ожидаемый полный порядок и не даёт требуемой проверки конкурентных изменений.
Нельзя считать его слепой вызов готовым безопасным режимом восстановления. Его `idx`
при вставке отсчитывается с нуля, тогда как сохранённые `Lesson Reference.idx`
после упорядочивания отсчитываются с единицы.

## Критерии приёмки будущего режима

- Полный подтверждённый checkpoint, источник и сайт совпадают. Все существующие
  уроки принадлежат ожидаемым курсу/главе, остаются черновиками без preview и имеют
  неизменные source snapshots, fingerprints, содержимое и ID.
- Создаются только разрешённые отсутствующие исходные ID. Ни заглушек, ни
  перенумерации, удаления, дубликатов или автоматического исправления чужих записей.
- Перестановка ссылок атомарна. Итоговые ID точно равны исходному порядку, `idx`
  непрерывны, а существующие тела уроков и снимки не переписываются.
- CAS/проверка конкуренции сравнивает ожидаемый полный набор и порядок ссылок под
  защитой транзакции. Одного `Course Chapter.modified` недостаточно, если операции
  с `Lesson Reference` не меняют родительскую метку времени. Чужое добавление,
  удаление или перестановка останавливает операцию.
- Журнал фиксирует начало и проверенный результат каждой мутации. Неизвестный
  результат записи немедленно останавливает запуск; повтор вслепую запрещён.
  Возобновление сначала сверяет фактические ID, snapshots и известное промежуточное
  состояние. Наличие уже созданного урока не разрешает создавать его повторно.
- Проверены повторный запуск без записей, остановка после создания до перестановки,
  неопределённая запись, конкурирующее изменение и точное сохранение исходного
  порядка, включая не возрастающие числовые ID в курсах 627 и 628.
- Публикация, настройки доступа, enrollments и access grants остаются вне операции.

До реализации и проверки этих критериев не обещать автоматическую вставку четырёх
средних уроков. Текущий разрешённый перенос 215 уроков от этой доработки не зависит.
