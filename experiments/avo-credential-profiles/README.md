# Доступ к паролям по должности

Системный администратор видит проверенный актуальный пароль при открытии
карточки пользователя. Для остальных сотрудников доступ определяется только
полем `custom_can_manage_credentials` назначенного профиля должности Frappe.
Прежнее прямое назначение роли `LMS Credential Manager` больше не даёт доступ;
публичный метод персональной выдачи права всегда отказывает. При каждом запросе
проверяется актуальная связь с должностью, поэтому отзыв действует сразу.
Только системный администратор может менять отметку в настройках должностей.

Изменение отметки не сохраняет Role Profile целиком и не пересобирает роли
его сотрудников. При назначении должности через штатный Frappe набор ролей
сотрудника формируется из должностей; перед назначением следует их проверить.
Пароль возвращается только после проверки текущего хеша; при отсутствии или
несовпадении зашифрованной копии он не показывается. Роль с этим правом не
может смотреть или менять пароли других сотрудников с привилегиями.

`test_stage.py` использует фиктивных пользователей и должность с откатом базы.
`create_context.py`, `Dockerfile`, `prepare_sites.py` и `deploy.py` сохраняют
воспроизводимую сборку, проверенные резервные копии и прежний образ для отката;
ключи, пароли, выгрузки и персональные данные в репозиторий не входят.

Проверка 11.11.2026: 48 тестов интерфейса и тесты серверной логики прошли;
на изолированной базе подтверждены доступ Administrator и System Manager,
запрет персонального назначения, доступ через должность, немедленный отзыв и
запрет изменения прав должности сотрудником. Поле установлено на всех трёх
сайтах, сервисы и проверка доступности прошли. Через MCP проверены права
Administrator и отказ старого метода. Визуальная проверка браузера не выполнена:
среда управления браузером не запустилась.
