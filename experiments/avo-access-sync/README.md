# Перенос связей МВЦ из архива АВО

Источник — приватный `exports/avo.sqlite`, последние успешные карточки доступа
МВЦ в проверенном диапазоне. Выгрузка относится к 13 октября 2026 года и не
подтверждает полноту всего аккаунта на текущую дату. Аккаунты не смешиваются;
сохранённый иностранный пример исключается, как и записи вне проверенного
диапазона. Применяются общий приватный список исключённых контактов и исключения
курсов из переноса содержимого.

`source_archive.py` читает SQLite только на чтение, по одной связи. `assigned`,
`accessible` и `hidden` сохраняются независимо, вместе с нулевой/ненулевой
задержкой, личными датами, заморозкой, точкой отсчёта и сдвигом. Исторический
статус не объявляется текущим. ФИО, почты, пароли, названия и исходные формы в
пакет не копируются. Повторные связи контакта с одним курсом не сливаются.

`export_payload.py` создаёт небольшой приватный gzip и контрольный манифест,
проверяет число строк, контрольные суммы и неизменность исходной базы. Существующие
выгрузки не перезаписываются. Манифест с реальными ID и сам пакет не входят в Git.

`target_sync.py` — доверенный оператор Python установленного bench. Он работает
только на МВЦ под Administrator и создаёт служебный реестр `AVO Course Access`.
Реестр доступен администратору на `/app/avo-course-access` и через MCP; обычные
ученики не получают доступ к чужим данным. Схема воспроизводима из исходника,
новый образ приложения для этого этапа не нужен. Строки сохраняются партиями
до 100 с проверкой исходных данных и ссылок перед подтверждением транзакции.

Соответствия ищутся по аккаунту и ID АВО отдельно в User, Contact и LMS Course.
Отсутствующий пользователь, контакт без учётной записи для входа и отсутствующий
курс получают отдельную причину ожидания. Исходный снимок неизменяем: другой
хеш или содержимое с тем же ID останавливают перенос. Повтор может дополнить
соответствия после переноса контактов, сохраняя уже применённые связи и доступы.

`run_store.py` запускается из `sites` установленного bench:

```text
<bench-python> <private-job>/run_store.py --payload <private-job>/access.jsonl.gz
  --manifest <private-job>/manifest.json --state <private-job>/state.json
  --events <private-job>/events.jsonl
```

Первый проход проверяет весь пакет до изменения схемы/записей. Небольшая
проверочная партия задаётся `--limit N`. Итог всего переноса подтверждается
числом записей и совокупной контрольной суммой, независимо прочитанной из Frappe.
Файл состояния содержит этап, PID, счётчики и безопасный код остановки. В журнале
только ID/счётчики/коды; неизвестная структура или неподтверждённая запись
останавливают работу сразу. Повтор сверяет реестр целиком, поэтому потерянное
подтверждение не создаёт дубль. Один серверный процесс защищён файловой блокировкой.

Само сохранение реестра не создаёт Enrollment, не открывает материалы, не меняет
черновики, не отправляет письма и не создаёт выдуманные учётные записи. Решение
владельца — считать общий срок курсов бессрочным, сохраняя личные сроки и
заморозки. Для применения прав используется штатная модель LMS после проверки
формулы открытия уроков; неизвестное правило не заменяется догадкой.

Проверенный первый этап 12.11.2026: сохранены 100992 допустимые связи и 1368202
личные строки уроков. Пять связей исключены по прежним решениям о курсах;
частный список исключённых контактов применён, совпадений в этом архиве нет.
Сверены все исходные payload перед подтверждением партий и повторно итоговая
совокупная сумма `e8a210cefac1f36984d7e8d9f13b2b70115cc3241f3a8803b63f0a2ac8b79faa`.
Партия из 20 связей проверена в базе; пример и роль только на чтение отдельно
прочитаны через MCP. В исходной
сверке соответствий 99739 связей нашли User/курс, 828 ожидают учётную запись,
425 — курс. Это состояния переноса, а не выдуманные доступы.

Проверка на реальном Frappe выявила две особенности схемы: у уникального поля
сбрасывается избыточный `search_index`, а пропущенные флаги DocPerm наследуют
разрешающие значения по умолчанию. Проверка принимает уникальный индекс; все
флаги прав задаются явно. Исправление начальных прав разрешено только для
нашего пустого реестра с точно известной конфигурацией. Существующий заполненный
реестр с неожиданными правами не исправляется автоматически.

## Применение записанных прав через LMS

`activation.py` и `run_activation.py` используют штатные LMS Access Policy,
LMS Access Grant и LMS Enrollment. Перед первым зачислением рабочий процесс
проверяет полноту всего реестра по исходному манифесту. Требуются МВЦ,
Administrator, включённая защита индивидуальных доступов и явный параметр
`--allow-general-unlimited`, отражающий решение владельца. Черновики остаются
черновиками, письма и новые User не создаются.

Проверенный компонент АВО получает `accessible` от сервера; поле подписано
«Доступен к просмотру (прохождению)». Поэтому переносятся только зафиксированные
разрешённые уроки: `assigned=true`, `accessible=true`, `hidden=false`. Граница
восстановления — позднейшая из личного начала и времени снимка. Это консервативная
граница миграции, не найденная исходная формула расписания. `Satisfied` в созданной
строке означает восстановленное разрешение; выполнение заданий не импортируется.
Закрытые уроки автоматически не открываются по непроверенной формуле `day_access`.

Замороженные, неизвестные, истёкшие и неоднозначные связи остаются в реестре с
причиной. По уточнению владельца от 12.11.2026 для каждой пары контакт–курс
актуальна связь с максимальным **числовым** ID. Она выбирается до проверки сроков,
заморозки и уроков. Старые записи получают `Superseded` и сохраняются в истории;
их права не объединяются с актуальными. Если последняя связь заморожена,
истекла или пока не сопоставлена, предыдущая не используется взамен.
Статус реестра обновляется отдельным проверяемым изменением метаданных; исходные
payload и контрольные суммы не меняются.
Отсутствующий ожидаемый урок требует разбора; заранее исключённые уроки пропускаются.
Существующие чужие правила, зачисления и изменения ручного доступа не перезаписываются.
Повтор проверяет собственные документы; обычное истечение личного срока обновляет
состояние реестра без удаления зачисления и без смены сроков гранта.

Рабочий процесс пишет состояние и журнал, прекращает работу после 10 допустимых
последовательных отказов. Неизвестный исход записи, конфликт контрольных сумм или
нарушение границ доступа останавливают его сразу. Пропущенные отказы обозначаются
`completed_with_issues`, а не полным успехом. Для этого этапа также не требуется
новый слой образа приложения: запускается опубликованный оператор в private.

При замене ранее запущенного обработчика можно передать `--skip-applied`:
полнота реестра всё равно сверяется, а уже подтверждённые доступы не создаются
повторно. Число пропущенных применённых записей сохраняется в состоянии и входит
в итоговую проверку охвата. В состояние также записывается правило
`highest_numeric_source_access_id`. Перед заменой старого процесса проверяются
его PID и точная команда; после остановки сверяются атомарно сохранённые связи,
гранты и зачисления. Основной импорт контактов не затрагивается.

Проверки: `python -m unittest test_source_archive test_export_payload
test_target_sync test_run_store` из этого каталога. Искусственные данные включают
чужой аккаунт, неизвестные типы/значения, повторные связи, конфликт снимков,
повторный запуск, обновление ожидающих соответствий, откат, неполную партию,
ошибки контрольных сумм и остановку без подтверждения сохранения.
