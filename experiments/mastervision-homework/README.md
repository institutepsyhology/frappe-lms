# Выпуск форм домашних заданий МВ

Рабочая ветка — `feature/course-access-20261117`. Базовый образ — `company-lms:course-access-7924cbb5`. Источник публикации — соответствующая ветка `institutepsyhology/frappe-lms` на GitHub.

Из каталога проекта на Windows команда пробной сборки:

```powershell
py -3 -B frappe-access-20261117/experiments/mastervision-homework/rollout.py trial
```

Команда выпуска после публикации коммита:

```powershell
py -3 -B frappe-access-20261117/experiments/mastervision-homework/rollout.py publish
```

Пробная сборка прошла на сервере 22 ноября 2026 года. У активного образа 52 слоя. Изолированный контейнер использовал уже распакованные слои, проверил интерфейс в Vitest и собрал его для работы. Образ с набором исходных файлов `72e10371c2802c0b4b75` прошёл все 14 проверок на `access-stage2.local`. Проверены переход к следующему уроку без добровольной работы, сохранение прежних требований к обязательным заданиям и тестам, приватные вложения и проверка отправленных работ. После сборок оставалось 2,71 ГиБ свободного места.

Производственный режим сверяет опубликованный коммит и содержимое действующего приложения. Собранный интерфейс используется повторно при совпадении исходника и базового образа. Собранный кандидат проходит проверки на изолированном сайте. На сервере создаётся и проверяется новая резервная копия трёх баз. Каждый новый архив перемещается в закрытый каталог резервных копий на том же диске. Существующие архивы сохраняются.

Перед переключением публикуются новые поля заданий с выключенными по умолчанию параметрами. Для шести служб используется действующий механизм проверки состояния и возврата предыдущего образа. После переключения на каждом сайте регистрируется только событие автоодобрения, компилируется русский каталог и сверяются контрольные количества и доступность трёх сайтов. Добавление самих форм, результатов учеников и индивидуальных прав — отдельные операции.

При первом выпуске старое подключение файла `lms/hooks.py` скрыло правило автоодобрения в новом образе. Исправленный выпуск проверяет, что подключённый файл совпадает с файлом исходного образа, а новый отличается ровно строкой расписания. Затем он снимает шесть дублирующих подключений этого файла. При откате до пересоздания служб восстанавливается прежний Compose. Проверки остальных подключений, файлов выпуска и регистрации обработчика контактов проходят до переключения и на активных службах. Исходный Compose сохраняется рядом с отчётом активации.

Повторный запуск сверяет права и контрольные суммы последней резервной копии всех трёх сайтов. Для того же выпуска и исходного образа она годится в течение двух часов. Сообщение об ошибке настройки указывает сайт, операцию и вид ошибки.
