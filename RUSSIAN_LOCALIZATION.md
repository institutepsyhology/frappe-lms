# Русская локализация LMS 2.64.0

## Задача и границы

Дополнить русский интерфейс установленной LMS, убрать английские подписи при первой загрузке и сохранить воспроизводимую версию в `institutepsyhology/frappe-lms`.

База: LMS 2.64.0, commit `7c46bb8f4976222b3f6aa84368551c424edaa194`; Framework 16.53.0. Содержание курсов, пользовательские имена, названия внешних продуктов и настройки доступа перевод не изменяет.

## Решение

1. Сверить `ru.po` с `main.pot` этой версии и заполнить все пропуски, сохранив подстановки, HTML и машинные идентификаторы исходных строк.
2. Исправить загрузку словаря: реактивный общий каталог обновляет уже показанные подписи, включая дочерние приложения редактора. Штатный ресурс и кеш переводов сохраняются.
3. Направить через переводчик отображаемые подписи меню и пустых состояний. Значения API, идентификаторы, статусы в проверках и ключи маршрутов остаются стабильными.
4. Для пользователя без собственного языка использовать системный язык сайта.
5. Проверить каталог, регрессионные тесты, сборку и реальные страницы перед переключением образа.

## Критерии приёмки

- Все строки актуального `main.pot` имеют перевод без fuzzy-записей.
- Подстановки в переводах совпадают с исходниками, каталог компилируется в MO.
- Уже показанное английское меню обновляется после получения русского словаря; повторная перезагрузка не нужна.
- Пустые состояния не смешивают русскую фразу с `Courses`/`Batches`.
- Пустое поле языка пользователя не даёт пустого словаря.
- Не изменены права доступа, данные курсов и контракты серверных методов.
- Изменения и результаты проверки сохранены в GitHub; предыдущий образ доступен для отката.

## Проверка каталога

```text
python check-russian-translations.py
```

Команда использует Babel из окружения Frappe. Результат содержит число строк, размер скомпилированного словаря и точный список ошибок.

Регрессионный тест загрузки словаря:

```text
cd frontend
node_modules/.bin/vitest run src/tests/asyncTranslations.test.ts --maxWorkers=1
```

## Сборка и развёртывание

На Docker-хосте с проверенным исходным образом и локальной копией этого репозитория:

```text
python3 russian-build-context.py /NEW/EMPTY/OUTSIDE/REPOSITORY --build
```

Путь вывода должен быть новым. Скрипт проверяет ID базового образа, собирает только изменённые исходники относительно установленной версии и создаёт манифест хешей. Зависимости берутся из существующего образа; сборка выполняется без сети. При иной исходной версии сначала проверить базу и обновить соответствующие константы.

`russian-deploy.py` — журналируемый однократный переход с проверенного старого ID на указанный новый ID. Запускать от root только на существующем LMS-хосте, после проверки сборки и публикации исходников. Скрипт сохраняет закрытую копию runtime-настроек, заменяет только `LMS_IMAGE`, пересоздаёт шесть сервисов приложения и проверяет HTTPS. При неудаче восстанавливает прежний файл и проверяет возврат старых сервисов. Повторный запуск после успешного обновления намеренно отклоняется, потому что исходный ID уже изменился.

Резервная копия этого обновления: `/opt/company-lms/backups/russian-release-20261023T233203828962Z`. Предыдущий образ сохранён. Для отката использовать закрытый `runtime.env.before` из этой папки как `/opt/company-lms/runtime/.env`, затем пересоздать только backend, frontend, websocket, queue-short, queue-long и scheduler и проверить сайты. БД, Redis и прокси не пересоздавать. Файлы настроек и резервные копии в GitHub не загружать.

## Переносы строк и сверка с образом

В GitHub исходники сохраняются с переносами LF; проверенная Windows-сборка и образ сохраняют исходные переносы, включая CRLF. Это изменение представления Git и послесборочной документации: повторная сборка и развёртывание для нормализации не выполнялись. Для сверки исходников сравнивайте SHA-256 после замены только CRLF на LF, сохраняя остальные байты. В `RUSSIAN_SOURCE_MANIFEST.json` карта `files` сохраняет исходные хеши 44 файлов сборки, а `git_lf_files` содержит хеши того же сборочного снимка после такой нормализации. `RUSSIAN_LOCALIZATION.md` дополнен после сборки, поэтому обе карты описывают его исходную сборочную версию; исходная проверка 44 файлов образа сохранена в `RUSSIAN_VERIFICATION.json`.
